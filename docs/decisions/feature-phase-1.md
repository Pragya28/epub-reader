## Architecture & scope

- **Framework stays Vite + React** — no Next.js. Vercel Functions in `api/` deploy alongside the SPA (one deploy target, per `02 - Architecture.md`).
- **All BE code in `backend/`; `src/` is FE only.** `api/` at the repo root holds only one-line re-exports, because Vercel detects functions only there.
- **`contracts/`** holds request/response zod schemas, inferred types, error codes and shared constants (72h rotation, 7-day idle expiry), imported by both sides.
- **`src/services/` stays client infra**; Sprint 3's client sync code goes in `src/services/sync/`.
- **`register` lands in Sprint 1** (Day 4) — the server only hashes an opaque proof, so nothing server-side waits on Sprint 2's encryption key; `setup` takes the proof from the start, so its contract never changes.
- **`recover` requires the device's own expired token**, not just its device id — device ids aren't secret.
- **An already-registered `deviceId` is rejected** by `register`; a device that cleared its data registers under a new id and its old row lapses through idle expiry.

## Layout

```
api/                  Vercel Functions — re-exports only, no logic
  setup.ts            export { default } from "../backend/handlers/setup"
  register.ts
  recover.ts
  invites.ts
backend/              all BE code (Node-only), own tsconfig
  handlers/           setup.ts, register.ts, recover.ts, invites.ts — validate via contracts, call auth + db
  auth/               auth.ts — token check, activity bump, 72h rotation, 7d expiry
  db/                 db.ts, migrate.ts, migrations/001_init.sql
  (tests colocated in __tests__/ next to each folder)
contracts/            shared FE/BE: zod schemas, inferred types, errors.ts, auth-constants.ts
src/                  FE only, unchanged
```

**Import rules:** `api/` → `backend/` · `backend/` → `contracts/` · `src/` → `contracts/` · no imports between `src/` and `backend/` · `contracts/` imports nothing but `zod` and itself (no Node or DOM APIs).
